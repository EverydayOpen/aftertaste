# Aftertaste v1 build plan (the contract)

Aftertaste is a free, open-source, offline macOS app (EverydayOpen's fourth, after Whydunit, Tirekick and Overstay) that finds
what an uninstalled app left behind (caches, preferences, containers, saved state, launch items ...), shows **why** each item
belongs to it with a confidence tier, moves the items you choose to the Trash with **Undo**, and hands you a shareable
**Trace Report**. It also has a read-only **Erase readiness** panel and is plain about what no app can erase. The product
decision, evidence, launch plan and kill tests are in the Whydunit repo's `docs/next/APP4.md` and
`docs/next/app4-research-*.md` (quoted below only where code depends on them). This file is the build contract for parallel
owners (§10). Where it disagrees with APP4.md, this file wins (§13 lists every disagreement); propose changes in your report
instead of diverging.

**What has run:** `AftertasteCore/Model` (the frozen types) and one placeholder test suite build and pass on Linux in Docker
(`bash tools/test_core_docker.sh`, 2026-10-03, no warnings). `tools/safety_greps.sh` passes on that tree and was checked
against injected violations (its self-tests). Nothing else exists yet. There is no Xcode on the dev machine, so every Mac and
App file is "written, not compiled" until a `macos-26` CI run says otherwise, and nothing about runtime behaviour on a real Mac
is claimed (AGENTS.md).

## 2. The product in one page

**Two verbs only: Move to Trash, Undo.** No permanent deletion of any kind, no helper, no root, no Full Disk Access
requirement, no network.

**Two ways in.** *Uninstall now*: drop an `.app` (or pick one). The bundle goes first, then its leftovers. *Orphans*: "Find
leftovers of apps that are gone". Both produce a **Preview** (the dry run) of `ResidueItem`s grouped by app, with tier, class,
size, the `~`-abbreviated path and a one-line **why**. Nothing moves until the user presses **Move N items to Trash**.

**Tiers** (`Tier`, §4.2). Precision over recall: a wrong deletion is the failure that kills the product.

| Tier | UI word | Meaning | Preselected | Executes |
|---|---|---|---|---|
| `high` | High | Exact bundle-ID match **and** regenerable or pure settings | **Yes** | bulk |
| `medium` | Medium | Likely this app's, may hold *your* data (Application Support, Containers, Scripts, synced prefs) | No | bulk, only with the per-app "Include my data" control and an acknowledgement in the confirm sheet |
| `low` | Review | Shared or ambiguous (Group Containers, name-only matches, vendor folders, "may be your only copy") | No | **one item at a time**, each with its own confirmation |
| `handsOff` | Hands off | Found, explained, never touched (Apple's, iCloud-synced, running, protected by macOS, locked, **launch agents in v1**) | No checkbox | never |
| `needsAdmin` | Needs admin | `/Library/...` items, privileged helpers, launch daemons, receipts | No checkbox | never; "Reveal in Finder", "Copy path" |

"Select all" means all High. Launch agents, launch daemons and privileged helpers are **listed, not removed** in v1 (owner
decision): removing a plist does not stop a job that is already loaded, unloading needs `launchctl` (forbidden), and the system
ones need an administrator.

**Honest copy.** What the app will and will not claim is APP4 §1.2, enforced by `tools/banned_phrases.txt` (§3.1 check 17,
§4.9). The Trace Report footer, verbatim: "This is a list of what was found in the places listed above. It is not proof that
anything was erased."

## 3. Safety rules (review + CI; all hard)

The product moves other apps' files. A bug here can take the wrong thing, so these are rules, not guidelines. S-numbers match
APP4 §3.5.

1. **S1 Two verbs.** `FileManager.trashItem` appears only in `Sources/AftertasteMac/Trasher.swift`; `moveItem` only in
   `UndoStore.swift` (and only Trash → recorded original, destination must not exist). Nothing else deletes, removes, unlinks,
   renames, copies, replaces, links, truncates, recycles, empties the Trash, or changes flags, permissions, ownership, xattrs or
   ACLs. No `removeItem`, `unlink`, `rmdir`, `rm` anywhere in `Sources/` or `App/`.
2. **S2 Preview is mandatory.** Only a `TrashPlan` built by `TrashPlanner.plan` from a `ScanResult` the user saw in this session
   can be executed, and only the ticked subset. No one-click, background, scheduled or on-launch clean; no Trash watcher.
3. **S3 Defaults.** Preselected = High only (`ItemSelection.preselected`; a unit test proves `tier != .high` is never preselected).
   Medium needs the per-app control **and** `acknowledgedMedium`. Review runs alone. Hands off and Needs admin have no checkbox.
4. **S4 Guard.** Every item is an immediate child of an allow-listed root (§4.3) or an app bundle in an app folder. Before
   acting, `Guard.verify` canonicalises the parent (`realpath`), `lstat`s the leaf and never follows it, requires the same device
   as its parent, a local volume (`MNT_LOCAL`), no immutable/append/restricted/dataless flag, not the never-list, not
   `com.apple.*` (minus the allow-list), owner uid == ours. The pure part is `GuardPolicy.check` (Core).
5. **S5 Re-verify immediately before acting.** The `FileStamp` taken by the scan (device, inode, type, size for files,
   mtime, link count) must be unchanged (`Stamps.same`); else the item is skipped as `changedSinceScan`. **No suspension point
   (`await`) between `Guard.verify` and `trashItem`** (pinned, §3.4). The remaining race is microseconds and is accepted and
   documented.
6. **S6 Running means blocked**, not warned. The owner's `allIDs` in `NSRunningApplication` **or** any process whose executable
   path is inside the owner's bundle or inside the item (read-only libproc, `Processes.swift`) blocks the item, evaluated at
   preview time and again right before every item (`RunningCheck.state`). Unreadable process list = blocked (fail closed). The
   app never quits, signals, or `launchctl bootout`s anything.
7. **S7 Shared data is protected.** Group Containers, vendor folders, plug-ins and frameworks are `low` or `handsOff` while any
   owner remains (live-owner index, §4.6). Shared roots (Adobe, Microsoft, Google, Mozilla, JetBrains, Ableton ...) are never
   above `low` and never preselected.
8. **S8 Orphan ceiling.** In an orphan scan an item can be `high` only if it is a **cache or log** with an **exact ID name**, no
   live owner, not modified for 30 days, and no volume that could hold apps is unmounted. Everything else is `medium` or lower.
9. **S9 Never Apple, never the system.** `com.apple.*` (minus `AppleAllowList`), `/System`, `/usr`, `/bin`, `/sbin`, `/private`
   (except read-only receipt rows), SIP/`restricted` items, Apple-signed bundles, `~/Library/Developer`, other users' homes,
   `~/.Trash`. Hard-coded in Core (`NeverList`); the user's keep-list only ever adds.
10. **S10 No privilege escalation.** No `SMAppService`, `SMJobBless`, `Authorization*`, `sudo`, `osascript`, XPC. `/Library`
    items are read-only rows. We never print a `sudo rm` line.
11. **S11 Never read file contents.** Scanning is `lstat`/`URLResourceValues`/`contentsOfDirectory` only. The only files read:
    `Contents/Info.plist` of `.app` bundles, launchd plists in the LaunchAgents folder, container metadata plists (each one
    file, 1 MB cap, `Identity.swift`, parsed in Core), the journal (`Journal.swift`) and the inventory
    (`InventoryStore.swift`). Materialisation is disabled process-wide at launch
    (`setiopolicy_np(IOPOL_TYPE_VFS_MATERIALIZE_DATALESS_FILES, IOPOL_SCOPE_PROCESS, IOPOL_MATERIALIZE_DATALESS_FILES_OFF)`,
    `Materialization.swift`, called first thing in `AftertasteApp.init`; pinned); `EDEADLK`/the dataless flag means "iCloud
    placeholder": record it, do not retry, do not read it.
12. **S12 iCloud is hands-off.** `Mobile Documents`, `CloudStorage`, `CloudDocs`, FileProvider and CloudKit caches are never
    listed, scanned or touched; their names exist only in `NeverList.swift`. "Not covered" says so.
13. **S13 Time Machine and snapshots are read-only**: only `tmutil listlocalsnapshots /` (§5.8), never any write verb.
14. **S14 Links, mounts, flags.** The link is the item, never its target. Never cross `st_dev`. Locked items are skipped with the
    reason and never unlocked. Firmlink spellings (`/System/Volumes/Data/...`) are normalised away and deduped by device+inode.
15. **S15 Write-ahead journal, fail closed.** Per item an `intent` line is appended and `fsync`ed *before* the move, a `result`
    line after. If the journal cannot be opened for append, or an intent cannot be written, **nothing moves**. 0600 file in a
    0700 folder, one file per month, append-only, `O_NOFOLLOW`. Holds home-relative paths because Undo needs them; it never
    leaves the Mac.
16. **S16 Undo** uses the recorded `resultingItemURL`: the Trash entry's device/inode/type must match the journal stamp, the
    destination must not exist (never overwritten: "Reveal in Trash" instead), emptied Trash = "Already emptied".
17. **S17 No overwrite in v1** (§1). Reserved primitives (`O_RDWR`, `O_TRUNC`, `pwrite`, `F_FULLFSYNC`, `F_NOCACHE`,
    `ftruncate`) appear nowhere.
18. **S18 No network, no telemetry, no paths in logs.** `print`, `NSLog`, `os_log`, `Logger` are forbidden (paths reveal which
    apps a person has had installed). `fatalError`/`assert` messages never interpolate.
19. **S19 Honest copy.** Banned phrases (APP4 §1.2) in everything the user can read; results say what happened ("Moved 14 items
    (212 MB) to Trash"), never what it means ("Your Mac is clean", "Data erased"). The primary button is never "Clean", "Erase",
    "Wipe", "Shred" or "Destroy"; it names the exact action and count.
20. **S20 Coverage honesty.** Every preview and report shows "Looked in N of M places. K protected by macOS." "Nothing found"
    is shown only when `Coverage.isComplete`; otherwise "Nothing found in the places I could read."
21. **S21 Fail closed.** Unreadable identity, unknown volume type, undeterminable running state, journal error, Guard failure:
    the item is `handsOff` or the run stops. Never "probably fine".
22. **S22 Order.** One run at a time, items sequential. In uninstall-now the `.app` goes first; if that does not move, nothing
    else does ("Nothing was removed, X is still installed"). A systemic condition (app launched, journal error, Trash
    unavailable) aborts the rest (`notAttempted`); an item-level error is recorded and the run continues.
23. **S23 Self-protection.** Aftertaste never touches its own bundle, journal, inventory, preferences or caches
    (`io.github.everydayopen.aftertaste*`, `Application Support/Aftertaste`).
24. **Naming/attribution rule** (§1) and no personal home paths in tracked files (`~`, `<scratchpad>`, a repo-relative path or the
    example user `jane`; `/Users/Shared` is allowed).

### 4.2 Tier assignment (Core `Scorer`, inside `Scan.analyze`)

Evidence only ever **lowers or keeps** a tier; nothing raises an item above its caps. In order:

1. **Match strength** from the rule's `key` (APP4 §3.3): T0 exact (`name == id`, `id + ext`, `id + "."` prefix,
   `TeamID.id`, a known group ID) → cap `high`; T1 proven (launchd `Program` inside the removed bundle, container metadata
   plist names the ID, receipt names the ID) → cap `high`; T2 structural (`<TeamID>` prefix, embedded-component ID,
   `<id>.{helper,agent,daemon,service,xpc,launcher,updater,installer,login,extension,plugin}`) → cap `medium`; T3 name
   (display-name variants at a boundary ` -_.`, length ≥ 5, not in `Hazards.commonWords`) → cap `low`. **T4 fuzzy does not exist.**
   A T3 match that has a T0/T1 sibling item for the same owner (e.g. the ID-named plist) may rise one step, never above
   `medium` and never above the rule ceiling.
2. `tier = min(rule.ceiling, matchCap)`.
3. **Guards** (APP4 §3.3 step 3, in order): never-list (→ `handsOff`, `appleOwned`/`neverList`/`iCloud`); the rule's ceiling being
   `handsOff` (launch agents in v1 → `listedOnly`) or `needsAdmin` (system roots); live-owner check against the installed index
   (same exact ID owned by a *different* live app → drop; helper/Team ID/vendor root/channel family/executable name → `low` or
   `handsOff` with `sharedWithInstalled`/`siblingInstalled`); `Hazards.sharedRoots` and shared updater caches → at most `low`;
   `irreplaceable` (path/size, §4.4) → at most `low`; `ShareRisk.high` → at most `low`; a protected container/group container
   whose contents cannot be read → `handsOff` (`protectedByMacOS`), name only, size `notMeasured`; a running owner → the group
   is `running` and every item is blocked at execution (the tier stays; the button is disabled).
4. **Orphan caps** (S8): `high` only for kind `cache`/`logs` with `exactID` + `noLiveOwner` + `staleMtime` (≥ 30 days, from the
   stamp or `SizeMeasure.newestMtime`) and `!coverage.volumeMayBeMissing`; everything else `min(…, medium)`; with a missing
   volume everything is `min(…, low)`.
5. **Uninstall-now:** the dropped bundle is `ruleID "APP"`, `kind .app`, `high` ("the app you dropped"), or `needsAdmin` when
   `bundleNeedsAdmin` (root-owned, typically Mac App Store). If another installed bundle shares the target's ID or channel
   family, the target's family-shared folders are `handsOff`/`siblingInstalled`. Dropping an app is a strong signal of intent but
   raises nothing above its tier: user data stays Medium and unticked.
6. `why` is built by `WhyText.line` from the strongest evidence: "Named exactly `com.example.notes.savedState`; no installed
   app has this ID."

### 5.5 `Trasher.swift` (the only `trashItem(`)

```swift
enum Trasher {
    /// Never throws. 1. Journal.begin (false → every item .notAttempted "The activity log is not writable, so nothing was changed.").
    /// 2. In plan order, per item, SYNCHRONOUSLY (the per-item function is not async): see the skeleton. 3. A systemic condition
    /// (owner launched, journal write failed, Trash unavailable on the volume) aborts the rest as .notAttempted. In uninstall-now,
    /// if the .app (first item) did not move, nothing else is attempted (S22). 4. Journal.end.
    static func run(_ plan: TrashPlan, home: String, keep: [String], now: @Sendable () -> Date,
                    progress: @Sendable (ItemOutcome) -> Void) async -> TrashOutcome
}
```
The per-item body, which the script pins (`UNDO`/`TRASH` pins in §3.4); names are exact, bodies are the mac owner's:
```swift
private static func moveOne(_ item: ResidueItem, in plan: TrashPlan, home: String, keep: [String], now: Date) -> ItemOutcome {
    // 1. Guard (pure policy + lstat + stamp). Anything but .ok returns without touching the item.
    switch Guard.verify(item, home: home, keep: keep) { /* .gone -> .alreadyGone, .changed -> .changedSinceScan, .blocked -> .blocked/.protectedByMacOS/.locked/.dataless */ }
    // 2. Running, read fresh.
    let owner = plan.owners.first { $0.bundleID == item.ownerID }
    if RunningCheck.state(owner: owner, itemPath: item.path, snapshot: RunningApps.snapshot()) != .notRunning { /* .blocked */ }
    // 3. Write-ahead. False -> nothing moves, the run aborts.
    guard Journal.intent(home: home, entry: /* verb .trash, phase .intent, path, stamp, why */) else { /* abort */ }
    // 4. The move. No await anywhere from step 1 to here.
    let url = URL(fileURLWithPath: item.path)
    var resulting: NSURL?
    do { try FileManager.default.trashItem(at: url, resultingItemURL: &resulting) }
    catch { /* map errno: EPERM/EACCES -> .protectedByMacOS, ENOENT -> .alreadyGone, EDEADLK -> .dataless, else .failed; Journal.result; return */ }
    // 5. Result, with resultingItemURL recorded for Undo.
    _ = Journal.result(home: home, entry: /* status .moved, trashedPath: (resulting as URL?)?.path */)
}
```
`resultingItemURL:` is captured and the error is never swallowed (`try?` is banned on that line). Whether in-process `trashItem`
works in a headless runner session, and what `trashItem` does to a symlink leaf (the link moves, not the target), are **VERIFY**
(§12); the probe workflow checks both on day 1.

### 7.2 Behaviour notes

- Nothing is read until the user starts a scan; the scan itself is read-only. The app refreshes the inventory (one JSON file) at
  launch and after each scan.
- A scan is cancellable, off the main thread, progress shown by place, with per-root time/entry budgets; a root that hits its
  budget is reported as partial, never silently truncated.
- After every move the app rescans; the result sheet shows the outcome, not the rescan. `NSWorkspace.didTerminateApplication`
  re-evaluates running state; there is no polling loop.
- Honesty copy: "found", never "cleaned"; "Moved to Trash", never "deleted"; "Looked in N of M places", never "all clear" with
  partial coverage; "belongs to" with the why, never "is junk".

## 13. Where this plan differs from APP4.md and the task brief (resolved here)

1. **Rules are Swift data, not `residue.json`** (APP4 §3.2): SwiftPM resources warn on Linux and need `Bundle.module`; Overstay's rule
   "data as Swift in Core" wins. A test may export `ResidueRules.all` to JSON as a golden file.
2. **Launch agents are listed, not removed, in v1** (the brief) even though APP4 rates user `~/Library/LaunchAgents` plists High with
   proof: U12's ceiling is `handsOff` (`listedOnly`), flipping to `high` in v1.1 is a one-row data change. The card's note therefore
   reads "Launch agents and helpers are listed, not removed." (APP4's "they need an administrator" is wrong for user agents).
3. **File names:** `Trasher.swift` (APP4: `Remover.swift`), `UndoStore.swift` (`Undo.swift`), `ReadinessProbe.swift`
   (`SystemInfo.swift`); `Materialization.swift`, `InventoryStore.swift`, `Processes.swift`, `RunningApps.swift` as in APP4.
4. **APP4 §3.6 row 2** ("`write(` nowhere in v1") cannot hold: the journal must write. `write(`/`fsync(`/`O_WRONLY|O_CREAT|O_APPEND`
   are allowed in `Journal.swift` only; every in-place-rewrite primitive stays banned.
5. **No Sparkle in v1** (APP4 §3.1 allowed it "only in `App/Updater.swift`"): unsigned betas, no Developer ID, Overstay's posture.
6. **Plist parsing lives in Core `Parsers`** (testable on Linux); `Identity.swift` only reads bytes (≤ 1 MB) and the signature.
   `Bundle(url:)` is not used anywhere; `Contents/Info.plist` is read directly.
7. **Window app first**, optional menu bar item (Overstay lesson e); close-last-window quits unless the item is on.
8. **Journal is one file per month** (`journal-YYYY-MM.jsonl`), per safety-ux S15 (Overstay's single `activity.jsonl` is not reused).
9. **iCloud `iCloud~` rows are not listed as Hands off** (safety-ux S12 suggested it; APP4 §3.2 says never scanned and grep 13 keeps the
   literals out of the code): iCloud is listed only under "Not covered".
10. **The banned-phrase scan also covers user-visible strings in `Sources/`** (not only `App/`), because Core's text builders are what
    the user reads; `BannedPhrases.swift` and whole-line comments are exempt.
11. **`ReadinessProbe` abandons a timed-out command instead of terminating it** (Tirekick's `ProcessRunner` calls `terminate()` and
    `kill`, which the signal grep forbids here).
12. **Tier naming:** the brief's "H/M/L" is `high/medium/low`; `low` displays as "Review" (APP4's word), and the two non-level states
    are `handsOff` and `needsAdmin`.
13. **Byte units are decimal** (Finder), as Whydunit's `ByteFormat`, not Overstay's Activity-Monitor binary units.
14. **Default for "Hide app names" is off, pre-ticked in the export sheet for any report covering more than one app** (a list of
    installed apps is itself sensitive; the single-app card is the shareable object and its name is the point).
15. **Orphan `high` is rarer than APP4's table suggests:** only caches and logs with an exact ID, 30 days stale (S8). Preferences and
    saved state of an *orphan* are `medium`; in uninstall-now they are `high` (the owner is known exactly).
