How it decides.

Every item carries a tier and a one-sentence reason. The tier is a word, never only a colour.

  1. The folder carries the app's exact bundle ID

    An exact match is the strongest evidence there is. It is the only thing that can make an item High.

    exact id

  2. It rebuilds or only resets

    Caches, logs and saved window state rebuild themselves; settings only reset the app to its defaults. Only these are ticked for you, and for an app that is already gone only caches and logs.

    cache · logs · state

  3. It may hold your data

    Application Support and Containers can hold documents, databases and recordings. Medium: unticked, and you look first.

    medium

  4. Several apps may share it

    Vendor folders and Group Containers can belong to an app that is still installed. Review: one item at a time.

    review

  5. It is Apple's, running, synced or protected

    Listed with the reason, never touched. Launch agents and helpers are listed too: removing them needs an administrator.

    hands off

Only High is ticked when a scan appears. Medium needs the per-app "Include my data" control. Review moves one item at a time. Read the rules in full.

A receipt with measured numbers only.

The Trace Report is a card, a Markdown file or JSON. Every figure on it was counted on your Mac during that scan. Below are its two sides; the card in the hero turns over as well.

On it

  • What was found

    The app's name and version, the number of files, their size, and how many launch agents and helpers were listed.

  • Where it looked

    "{{coverageSample}}" A partial look is never called a clean result.

  • When and on what

    The macOS version and the scan date. "Hide app names" swaps the names for App 1, App 2.

  • One honest sentence

    "This is a list of what was found in the places listed above. It is not proof that anything was erased."

Never on it

  • A verdict

    No "clean", no "gone", no score. The card says what was counted and stops there.

  • Your home folder's name

    Paths use ~. The export scrubs the rest.

  • An upload

    Nothing is sent. You copy the image or save it yourself.

What it reads. What it never does.

The rules are written down, and a script in CI fails the build when code breaks one of the mechanical ones.

Reads

  • Folder and file names and sizes

    In the places of your Library it lists. Never what is inside a file.

  • The list of installed apps

    Their names, bundle IDs and signatures, so it knows what is still in use.

  • A few small property lists

    An app's Info.plist, the launch agents you have and container labels, one file each, 1 MB at most.

  • Three read-only system commands

    For the Erase readiness page: FileVault status, the disk's type and the count of local snapshots.

Never

  • Ask for permissions or a password

    No administrator rights and no helper. It never requires Full Disk Access. When macOS blocks a folder it says so and offers an optional Settings shortcut; it works without it. Folders macOS protects are named, not guessed.

  • Connect to a network

    No telemetry, no account, no update check.

  • Read file contents

    Scanning uses names, sizes and dates only.

  • Delete anything

    Trash only, with Undo. No overwriting, no emptying the Trash.

  • Touch iCloud or Apple's own data

    iCloud folders, Mail, Messages, Photos and Keychains are never listed as leftovers.

Every rule, and what the log holds.

What no app can erase.

Moving to the Trash does not erase anything, and no app can reach every copy of a file on a modern Mac. Here is who could still read old data, and what helps.

  • Someone using your unlocked Mac

    They can open anything you can open, including the Trash and files you moved there.

  • Someone with your Mac but not your password

    With FileVault on, or on a Mac that encrypts its storage, reading the disk needs your login password or recovery key.

  • The next owner of your Mac

    Run Erase All Content and Settings first. Moving files to the Trash does not remove them.

  • Time Machine and local snapshots

    Copies there are outside what this app can reach. The local snapshot count in Erase readiness tells you whether any exist.

  • iCloud

    Copies in iCloud are managed in System Settings, not here.

Need to be sure? On a Mac that offers it, Erase All Content and Settings destroys the key. Why, in plain words, with sources.

Nothing leaves your Mac.

Aftertaste has no server to talk to. This website has no analytics, no cookies and no third-party requests.

  • No network

    No telemetry, no account, no update check. A check in CI fails the build if a networking API appears.

  • No permissions required

    No elevated rights. It never requires Full Disk Access. When macOS blocks a folder it says so and offers an optional Settings shortcut; it works without it.

  • A local journal

    Every move is appended to a file only you can read, so Undo works. It stays on your Mac.

  • Names off on request

    "Hide app names" removes app names from the card and the exported report.

02 · Questions

Before you try it.

Short answers. The long ones are in the guides and on the rules pages.

Does dragging an app to the Trash remove everything?

No. It removes the app. The caches, preferences, saved state and containers the app wrote in your Library stay, and so can launch agents and helpers. In the Homebrew cask data, 4,734 casks list leftover paths to remove, and about three in four of those name a Preferences file. The folder-by-folder answer.

Will this delete my documents?

It never deletes: items go to the Trash and Undo puts them back until you empty it. Documents can still sit inside Application Support or a Container, so those are Medium: unticked, labelled "may be your only copy" where that is likely, and moved only after an extra switch and a tick.

Why is something listed but not ticked?

Only items that rebuild themselves or are only settings, and carry the app's exact bundle ID, are ticked. Everything else is listed with its reason so you can decide: Medium may hold your data, Review may be shared, Hands off and Needs admin are never moved.

Why can't it remove a launch agent?

Deleting the file does not stop a job that is already loaded, and stopping one needs a command Aftertaste never runs. System-wide ones need an administrator. They are listed with the reason, and you can reveal the file in Finder.

Does it need Full Disk Access?

No. It never requires Full Disk Access. When macOS blocks a folder it says so and offers an optional Settings shortcut; it works without it. macOS protects some folders, mostly Containers and Group Containers, and what an ordinary app can read there differs between versions. When a folder cannot be read, the report says "protected by macOS" and the coverage line counts it, instead of saying nothing was found.
