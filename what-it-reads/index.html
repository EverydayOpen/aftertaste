04 · What it reads

What Aftertaste reads, and what it never does

Aftertaste moves other apps' files, so a bug could take the wrong thing. These are the rules it is built under. Most of the mechanical ones are checked by scripts that run in CI and fail the build when code breaks them.

In development. No public release yet. The matching and planning logic has automated tests. Nothing has run on a real Mac with a real Library yet, so read everything described here as the design, not as proof that it works. The changelog will say what testers have tried.

The short version

  • Two verbs. Move to Trash and Undo. Nothing is deleted, overwritten or emptied.
  • Preview first. Nothing moves until you press the button for the items you ticked.
  • Only what rebuilds itself or is only settings is ticked, and every item is checked again right before it moves.
  • Nothing leaves your Mac. No network, no account, no telemetry, no helper, no administrator rights.
  • It says where it could not look, and what no app can erase.

What it reads

  • Names, sizes and dates

    It lists folders and files in the Library places it knows (caches, preferences, application support, containers, saved state, logs, launch agents and a few more) and notes their size and dates. It never opens a file to read what is in it.

  • The installed apps

    The Applications folders, to learn each app's name, bundle ID, version and, from its signature, its developer ID and app groups. This is how it tells an app that is gone from one that is still in use.

  • A few small property lists

    An app's Info.plist, the launch agent files in your LaunchAgents folder, and the label file inside a container. One regular file each, never a link, 1 MB at most.

  • Which apps and programs are running

    So it can refuse to move anything whose app is running. If it cannot tell, it treats the item as running.

  • Three read-only system facts

    For the Erase readiness page: whether FileVault is on, whether the disk is flash or spinning, and how many local snapshots exist. See the three commands.

What it never does

  • Ask for permissions

    No Accessibility, Automation or administrator password, and no helper. It never requires Full Disk Access. When macOS blocks a folder it says so and offers an optional Settings shortcut; it works without it. Aftertaste is not sandboxed, because a sandboxed app cannot see other apps' leftovers, and it needs no entitlement. Some macOS versions protect other apps' Containers and Group Containers. Those folders are named as "protected by macOS" and counted in the coverage line, never guessed at.

  • Use the network

    No telemetry, no account, no update check. "Check for updates" opens the releases page in your browser, and only when you click it. A script rejects the common networking APIs in CI.

  • Read file contents

    Scanning uses names, sizes and dates. When iCloud has not downloaded a file, it records that and moves on.

  • Delete, overwrite or empty

    Items go to the Trash and nothing else happens to them. There is no overwriting, no emptying of the Trash, no permanent removal, and no command that deletes.

  • Touch iCloud, Apple's data or its own

    iCloud folders, Keychains, Mail, Messages, Photos and anything named com.apple.* are never listed as leftovers. Aftertaste never moves its own journal, inventory or preferences.

  • Change a setting or a process

    It does not toggle iCloud or system settings, change permissions, stop or signal a process, or run a launch command. Launch agents, daemons and privileged helpers are listed, not removed.

  • Run a shell

    The only programs it starts are the three below, by absolute path, with a fixed argument list.

  • Promise what it cannot

    It reports what was found and what moved. It does not say your Mac is clean, and it does not say anything is gone for good.

How a move works

  1. You confirm exactly what will move

    The confirm sheet lists every item in plain words. Medium items need the per-app "Include my data" control and an acknowledgement. Review items run one at a time.

    confirm

  2. Each item is checked again, right before it moves

    Same device, file number, type, size and date as at the scan. Its folder is an allowed Library folder, it is not a link that leads elsewhere, it is local, unlocked and not an iCloud placeholder, and its app is not running. If anything changed, the item is skipped and the journal says so.

    lstat

  3. The journal gets a line first

    An intent line is written and flushed before the move, a result line after. If the journal cannot be opened for appending, nothing moves.

    0600

  4. The item goes to the Trash

    One item at a time, with the system's own call. Nothing in the Library is removed in any other way.

    trashItem

  5. Undo puts it back

    History moves the item from the Trash to the place it came from, using the location the system recorded. It never overwrites: if something is already there, it offers to reveal the item in the Trash instead.

    undo

The call that moves an item to the Trash lives in one source file, Trasher.swift, and CI fails if it appears anywhere else.

The safety rules

  1. Two verbs only

    Move to Trash, and Undo. No remove, unlink or delete call exists in the code, and a check fails the build if one appears.

    trashItem

  2. The preview is mandatory

    Only a plan built from a scan you saw in this session can run, and only for the items you ticked. No one-click, background, scheduled or on-launch clean.

    plan

  3. Only High is ticked

    Medium needs a switch and an acknowledgement. Review runs alone. Hands off and Needs admin have no checkbox.

    high

  4. Every item must pass the guard

    An immediate child of an allowed folder, never a followed link, the same disk as its folder, a local volume, not locked, not on the never-touch list, owned by you.

    lstat

  5. Running means blocked

    If the app, or any program run from inside it, is running, its items do not move. Aftertaste never quits or signals anything.

    running

  6. Shared data is protected

    Group Containers, vendor folders and plug-ins stay Review or Hands off while another app may need them.

    shared

  7. iCloud is hands off

    Its folders are never listed, scanned or touched. A move there would sync to every device.

    icloud

  8. The journal fails closed

    A file only you can read, one per month, append-only, in a folder only you can open.

    0600

  9. Links and mounts are not followed

    A link is the item, never its target. Nothing crosses onto another disk.

    O_NOFOLLOW

  10. Unknown means no

    An unreadable identity, an unknown volume type, a running state it cannot determine or a guard failure makes the item Hands off, or stops the run.

    fail closed

  11. No overwriting in version 1

    Aftertaste does not fill free space and does not overwrite files. On flash storage that would not do what it sounds like. Why.

    none

  12. No shell, three commands

    Absolute paths, argument lists, read-only.

    3 commands

The three commands

The Erase readiness page runs exactly these, with nothing added, and reads their output. They change nothing.

/usr/bin/fdesetup status
/usr/sbin/diskutil info -plist /
/usr/bin/tmutil listlocalsnapshots /

The journal

Every item of every run, including skipped and failed ones, is appended to a file in ~/Library/Application Support/Aftertaste/, one per month, readable only by you and never inside iCloud. A line holds the time, what was done, the item's path under your home folder, its size and the result. Undo needs the real path, so the journal keeps it; the journal never leaves your Mac. The list of apps Aftertaste has seen installed is kept next to it. A Trace Report is different: its paths use ~, and "Hide app names" replaces app names with App 1, App 2.

Privacy

The app

It collects nothing and sends nothing, because it makes no network connection at all. The card and report are made on your Mac. Nothing is shared unless you copy or save one yourself.

This website

It sets no cookies, runs no analytics, loads no third-party scripts, fonts or images, and makes no request beyond its own files. A strict content policy enforces that in your browser. The site is hosted on GitHub Pages, which keeps its own server logs under GitHub's privacy statement; we do not receive them.

Why you can check all of this

  • It is MIT licensed and has no third-party dependencies in version 1.
  • The rules are written down in the repository, and the mechanical ones are scripts you can run yourself.
  • Builds come only from GitHub Releases, with a checksum in the notes.

To report a vulnerability, or a way to make Aftertaste move something it should not, see the security policy.
